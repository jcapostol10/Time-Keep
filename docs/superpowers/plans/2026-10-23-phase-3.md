# Phase 3 — Reports, dashboard and exports: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Summary, Detailed and Weekly reports that always agree with each other and with the tracker, exportable to CSV/Excel/PDF and shareable by link; a dashboard with a Me view and a live Team view; the project Status tab fed by the same engine.

**Architecture:** One SQL aggregation in `apps/web/src/server/reports.ts` over `time_entry` (scoped by workspace, the viewer's role deciding whose entries), shaped by pure builders in `packages/core/src/reports.ts` (query schema, range presets, buckets, grouping tree, weekly grid). Pages SSR the first result into react-query under the tracker's `entries` key prefix and refetch through `/api/w/[slug]/reports/*`. Exports read one row record per report (`packages/core/src/report-export.ts`); small ones stream, large ones become `export_job` rows run after the response and stored in a private bucket. Share links store a hashed token, the effective query and the creator's preferences, and render on a public page without the app shell; the PDF prints that page's components as static HTML in headless Chromium.

**Tech Stack:** Next.js 16 App Router, React 19, Drizzle/Postgres, zod 4, react-query, Recharts, exceljs, puppeteer-core + @sparticuz/chromium, @aws-sdk/s3-request-presigner, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-23-phase-3-design.md` (six owner decisions agreed 2026-10-23).

## Global Constraints

- Every query is scoped by `workspaceId` and role-checked; a member's report is forced to `userIds = [self]` inside the engine, never only in the UI (CLAUDE.md invariant 3).
- Timestamps are UTC; date keys and buckets are computed in the viewer's timezone in SQL (`(start AT TIME ZONE tz)::date`); a midnight-crossing entry counts under its start date, as the tracker does. No `n * 86_400_000` on instants; day maths via `packages/core`.
- Reports count stopped, non-deleted entries only (`"end" IS NOT NULL AND deleted_at IS NULL`).
- Time entries are written only through `apps/web/src/server/time-entries.ts`; the Detailed report's inline edit goes through `updateEntryAction`.
- Money stays out: every total is a record `{ durationSeconds, billableSeconds, entryCount }` so Phase 4 adds measures as keys.
- Grouping keys, sort columns and export formats are fixed vocabularies validated by zod; nothing from the URL reaches SQL as text.
- Share tokens are 32 random bytes; the database stores `sha256(token)` only; unknown, expired and revoked tokens get the same 404 page.
- Migrations expand only; every new table calls `.enableRLS()` (`rls.test.ts`).
- `pnpm test` never points at Supabase; e2e stays in the `@e2e.test`/`@demo.test` tenants; the perf seed uses `@perf.test` and refuses a non-local URL.
- Every page works at 375 px; charts are legible in dark mode (theme tokens).
- e2e: fixtures from `e2e/fixtures.ts`; a feature starts with unticked lines in `docs/E2E_COVERAGE.md` and failing tests; tick only after the test was seen failing; the suite stays under 10 minutes on a preview.
- New env: `S3_EXPORT_BUCKET` (default `timekeep-exports`), `EXPORT_JOB_THRESHOLD` (rows, default 10000), `CHROME_PATH` (local only); all documented in `.env.example`, none in git.

## Review Focus

1. **A member who edits the URL to another user's id** (`userIds=<other>`) must still see only their own time, in all three reports, the dashboard and any export or share link they create. Test: Task 4 ("a member's query is forced to their own entries whatever userIds says") and Task 6 e2e ("a member cannot widen the Users filter by URL").
2. **A revoked, expired or never-issued share token** must render the same "no longer available" page with status 404 and no hint which it was; a link whose creator left the workspace reads as revoked. Test: Task 13.
3. **Presets and buckets across a daylight-saving change and a year boundary**: "this week" and "last month" in New York around 2026-03-08 and 2026-11-01, "this year" on 1 January, a midnight-crossing entry under its start date. Test: Task 1 (pure) and Task 4 (SQL).
4. **Tag grouping and AND/OR filters with multi-tag entries**: an entry with two tags appears under both groups and once in the total; AND requires every tag, OR any; "No tag" is a group. Test: Tasks 1 and 4.
5. **Exports at the limits**: a request over the row threshold becomes a job (never a timed-out stream); a share-page viewer over the threshold is refused with a clear message; a streamed file never exceeds 4 MB. Test: Task 11 (integration) and its e2e.
