# Backlog cleanup, branch 3 (money) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native execution, already chosen) to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every `b3` entry in `docs/BACKLOG.md`: rates, cost, currencies, budgets, expenses and invoices.

**Architecture:** No new features. Each item is a small fix in the module that owns it, proven by a test that fails first. One additive migration (0023) carries two columns. Paths are under `apps/web/src/` unless they start with `packages/` or `docs/`.

**Tech stack:** Drizzle + Postgres, Vitest integration tests (one run at a time), Playwright on a production build, fflate, `@aws-sdk/lib-storage` (new, for the streamed zip).

**Spec:** `docs/superpowers/specs/2026-11-17-backlog-cleanup-design.md` (rulings 1–17, "Branch 3").

## Global constraints

- Money is integer minor units; nothing is converted; `time_entry`, `expense` and the invoice tables keep their single writers (the coverage tests stay green).
- Migration 0023 is additive only and goes through `migrate.yml` with the owner's approval before the merge.
- Every fix has a test seen failing first, except the items marked "no failing test possible", which name their guard.
- `pnpm test` never points at Supabase. The repo is public: no secrets, no production names in logs.
- Each backlog entry moves to Done, with date and commit, in the commit that finishes it.

## Rulings made while planning (ledger them at setup)

- **R-A (6b, no lock around `evaluateBudgets`):** closed as covered. The daily claim in `daily_job_run` lets one run per workspace and local day in; only the e2e `force` hook skips it. *Cost if wrong:* a partial unique index on budget kinds.
- **R-B (6b, weekly sampling):** the premise was wrong (points are cumulative, so nothing is lost). The fix is cosmetic: sample on the workspace's week ends, plus today.
- **R-C (6c, `expense.write`):** the two matrix rows are identical today, so no behaviour test can fail. `expenseScope` and the create action assert `expense.write`; a source check is the guard.
- **R-D (6c, EXIF):** current browsers already apply orientation in `createImageBitmap`. Pass `imageOrientation: "from-image"` explicitly; no e2e fixture. *Cost if wrong:* a rotated receipt on an old browser.
- **R-E (6d, "sent" date):** the workspace timezone, like every other invoice date, not the viewer's.
- **R-F (6d, notes after sending):** notes freeze at send (the PDF is what was sent, ruling 12); the external reference stays editable. *Cost if wrong:* one entry back in `AFTER_SEND`.
- **R-G (6d, captured attachments):** `captured_email.attachments` stores metadata only (`filename`, `contentType`, `size`), never bytes: the table is shared with production.
- **R-H (migration shape):** `rate_recalc_job.kinds text[] not null default '{billable,cost}'` (the spec's name), so old rows mean "both".

## Review focus

1. A cost-only job folded into a waiting billable job must re-rate both, from the earliest date; a failed job's kinds must survive its delete.
2. Versioned receipt keys: every reader (`receiptUrl`, the zip, the purge) must use the stored key; old rows with deterministic keys must still open.
3. `sendInvoice` rendering outside the transaction: a concurrent edit must be refused, never sent with a stale PDF, and a losing send must not overwrite the winner's file.
4. The currency lock: four writers take it in the same order; the CONFIRM refusal still rolls back cleanly.
5. Keeping a zero foreign amount in `otherAmounts` changes Weekly, the dashboard and exports; masked viewers must still get nothing.
