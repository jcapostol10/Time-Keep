# Backlog cleanup, branch 2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the backlog's **b2** entries (approvals, time off, attendance, targets, kiosks, the daily cron) and drop the columns branch 1 stopped using.

**Architecture:** Two migrations, generated separately so drizzle-kit never asks about renames:
- 0021, the contract: drop `task_assignee` and `workspace_settings.task_creators`.
- 0022, additive: `kiosk.tag_id` and the `daily_job_run` table.

Both are applied to the shared database through `migrate.yml`, with the owner's approval, before the preview runs. Everything else is service and UI fixes. Each fix gets a test that fails first: Vitest for services, e2e where only a browser shows it.

**Tech Stack:** Next.js 16, Drizzle, Postgres, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-backlog-cleanup-design.md` (rulings 5, 8, 9; "Branch 2"). The code map is the b2 explorer report; each task below names its files.

## Global Constraints

- Follow the CLAUDE.md invariants: workspace scoping, the permission matrix, time entries written only through `time-entries.ts`, expand then contract.
- Supavisor runs in transaction mode: only `pg_advisory_xact_lock`, never session locks.
- Every outbox email keeps its dedupe kind. Retention never deletes a row whose kind is a dedupe key.
- Tick a coverage line only after its test was seen failing with the guarded behaviour broken.
- When an entry is fixed, move it in BACKLOG to Done, with the date and the commit, in the same commit.

## Rulings made in this plan

- **R1. Auth and invitation emails stay in the request.** Moving them to the outbox would:
  - retry links after they expire (the magic link lasts 15 minutes, verification and reset 1 hour; retries run at 30 and 120 minutes);
  - store live tokens in plain HTML;
  - lose the per-address "failed" feedback that invites and the user import show.

  Better Auth already logs and swallows a verification or reset send failure. The entry closes as a ruling.
- **R2. The daily jobs run hourly.**
  - A workspace runs once per local day, in the first hourly run at or after 07:00 in its timezone.
  - The run is claimed in `daily_job_run (workspace_id, local_date)` with `INSERT … ON CONFLICT DO NOTHING RETURNING`. That also serializes a cron delivered twice.
  - A claim older than 2 hours with no `finished_at` may be taken again, so a run killed mid-way retries.
  - The test hook and the existing tests pass `force: true`, which skips the hour gate and the claim. `purgeKiosk`, outbox retention and the drain run every hour.
- **R3. The unsubmitted reminder catches up.** It reminds the most recent closed period if today is within 3 local days of the period's end, so a missed day is not lost. Late additions later in the week still do not remind.
- **R4. Outbox retention.** Rows older than 30 days that are SENT, SKIPPED or FAILED have `html` and `text` set to `''` (both columns are NOT NULL). The row itself is kept, because its `kind` is a dedupe key.
- **R5. A period with a running timer cannot be approved.** The reviewer is told who is still timing. The submit path already refuses a running timer.
- **R6. Approval of time off re-checks the balance** under the person's lock (`timerLock`, sorted) and refuses with "This would take <name> below zero." when the policy forbids a negative balance.
- **R7. A workspace timezone change while periods are APPROVED asks first.** The server returns `fieldErrors.confirmTimezoneChange`, and the settings form asks through its existing confirm pattern, saying approved periods' edges move by the zone difference.
- **R8. An unassigned policy.** The preview answers the 404 as "You are not on this policy." The request dialog, with no policy assigned, says to ask an admin. Assignment stays the rule.
- **R9. Locked empty cells** come from a new read, `/api/w/[slug]/time-entries/locked-days?from&to&userId` (`lockedDays`: `{ [dayKey]: reason }` for the target's scope, under the tracker's `entries` prefix). The range cache's shape is unchanged.

## Review Focus

1. **Two cron deliveries in the same hour run a workspace once.** Pinned by `daily-jobs.test.ts` "two runs in the same hour claim the day once".
2. **The 07:00 gate is in the workspace's zone,** and a workspace west of UTC runs on its own morning. Pinned by "runs each workspace at its own 07:00".
3. **A kiosk's default tag that was archived is refused at save.** At punch time it is refused like any archived tag. Pinned in Task 2.
4. **Outbox retention never breaks a dedupe.** A reminder whose old row was blanked is still not re-sent. Pinned in Task 4.
5. **A cancelled note prompt on a multi-owner delete leaves the view matching the server.** Pinned in Task 6.
