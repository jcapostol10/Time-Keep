# Backlog cleanup, branch 1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the backlog's **b1** entries: tracker, timesheet, calendar, catalog, auth, tasks by group and CI.

**Architecture:** Each fix comes with a test that fails first:
- a pure helper with a Vitest unit test when the fix is client logic (the web Vitest has no DOM);
- a DB integration test when the fix is in a service;
- an e2e test when only a browser shows it.

The `task_assignee` / `task_creators` removal is the **expand** half of the contract: this branch stops reading and writing them and drops them from the Drizzle schema. The `DROP` migration ships in branch 2, after this code is live everywhere.

**Tech Stack:** Next.js 16, React 19, react-query, Drizzle, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-backlog-cleanup-design.md` (section "Branch 1" and rulings 15–17). The code map with file:line references is the explorer report, summarised per task below.

## Global Constraints

- CLAUDE.md invariants and conventions hold, in particular:
  - Time entries are written only through `server/time-entries.ts`.
  - Date maths only through core helpers.
  - `react-hooks` v7 rules apply (no impure render, no synchronous `setState` in effects).
- Expand before contract: no migration in this branch, and `pnpm db:generate` is never run here.
- Every new e2e test gets a line in `docs/E2E_COVERAGE.md`, ticked only after it was seen to fail with its behaviour broken.
- When an entry is fixed, move it in `docs/BACKLOG.md` to Done, with the date and the commit, in the same commit.
- Gate: `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test`, then the e2e suite on a production build (`pnpm --filter @timekeep/web build && CI=1 AUTH_RATE_LIMIT_ENABLED=false pnpm --filter @timekeep/web e2e`).

## Review Focus

1. **Stored timesheet rows are keyed by workspace, person and week.** Rows added while viewing another person, or in another week, never appear elsewhere. A stored row whose project is no longer offered is dropped silently. Pinned by the `storedRows` unit tests (Task 3).
2. **An optimistic calendar or timesheet change that the server refuses goes back.** This covers a locked period, a cancelled note prompt and a validation error. Pinned by the `range-cache` restore test and the e2e refusal test (Task 4).
3. **Copy last week, run twice, copies nothing the second time.** An entry already in the target week with identical details is not duplicated, and an unrelated entry already there stays. Pinned in Task 9.
4. **A hand-edited `sort=` or `dir=` in the URL falls back to start/desc.** It never reaches SQL. Pinned by `parseDetailedSort` tests (Task 11).
5. **A manager who creates a project becomes its manager.** That opens approvals of other people's time on that project to them. This is intended (they created it), but the approvers test must show it is limited to that project (Task 13).
