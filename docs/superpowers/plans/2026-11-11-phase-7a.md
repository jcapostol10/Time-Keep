# Phase 7a — Schedule: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Planners schedule people on projects over the coming weeks, see who is over or under capacity day by day, and publish the plan. Members see their own published plan in My schedule and on the Calendar.

**Architecture:**
- **Tables:** three new tables in migration `0020_phase7a`: `assignment`, `milestone` and `assignment_publish`.
- **Drafts:** an assignment is a published row or a draft. A draft edit of a published row names it (`replaces_id`), and a draft tombstone deletes it (decision 9).
- **One writer:** `server/schedule/assignments.ts` writes `assignment`; `server/schedule/publish.ts` applies drafts under a workspace advisory lock and queues one email per changed person.
- **Pure maths:** core `schedule.ts` holds where an assignment's minutes fall (working days, holidays, a total spread, weekly recurrence), capacity, heat and the date edits. The drag hook and the dialog both call it.
- **One read:** `server/schedule/read.ts` builds the working plan or the published plan for a range and the viewer's scope, with each person's capacity per day.

**Tech Stack:** Drizzle + Postgres, `packages/core` (Vitest), Next.js 16 route handlers and server actions, react-query, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-11-phase-7-design.md` (decisions 1–18, Data model, Access rules, Tests: the 7a parts).

## Global Constraints

- Assignment dates are **date keys** (`YYYY-MM-DD`, `date` columns, no time zone). Date maths only through core (`addDaysToKey`, `dateKeysBetween`, `weekdayOfKey`); never `n * 86_400_000` on an instant.
- Minutes are integers. A day holds at most `1440`. A total is spread `floor(total / n)`, with the remainder one minute at a time to the earliest days.
- `assignment` is written only by `server/schedule/assignments.ts` and `server/schedule/publish.ts` (`schedule-writers-coverage.test.ts` enforces it).
- **Who:**
  - `schedule.viewTeam` on `{ kind: "none" }`: owner, admin and manager yes; member `no` (403).
  - `assignment.write` on `{ kind: "entry", userId, projectId }`: owner and admin yes, manager `scope`, member `no` (403).
  - `schedule.publish`: owner, admin and manager yes; member no.
  - `milestone.manage`: `PROJECT_MANAGERS` on the project resource.
  - A row outside the scope is a 404, never a 403.
- **Reads:**
  - Members read published rows only.
  - Planners read the working plan: drafts that are not tombstones, plus published rows no draft replaces.
  - Every reader uses `workingPlanWhere` or `publishedPlanWhere` from `server/schedule/plan-sql.ts`.
- A range read is at most 91 days (13 weeks). A single assignment spans at most 366 days. A series repeats every 1–4 weeks until a date at most one year after its first start.
- The migration is additive. Previews never migrate: **stop after Task 2**, push, and ask the owner to approve running Migrate shared database on the branch.
- Tests first. E2E: unticked lines in `docs/E2E_COVERAGE.md` and a failing spec before UI code. A line is ticked only after its test was seen to fail with the behaviour broken; the commit message records the break.
- Every page works at 375 px (the grid scrolls sideways inside its card).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Finished branches merge to `main` (`--no-ff`) and push; the branch is then deleted remote and local.

## Review Focus

1. **A total over a span with a holiday and a weekend:** 20 h from Monday to the next Monday, with Wednesday a holiday for the person (not for a colleague). 6 working days, so 200 minutes each, nothing on the holiday or the weekend, and the colleague gets 7 days. Task 1 and Task 3 tests.
2. **A manager edits a published assignment twice, then deletes it.** One draft replaces it and is edited in place, then becomes a tombstone. The member's view still shows the published row until Publish, which then removes it and emails the member a list without it. Task 3 test.
3. **A recurring series that only partly overlaps the range:** every 2 weeks until a date mid-range. The read counts only the occurrences in range, cut to the range, and a TOTAL is spread over each whole occurrence, not over the cut. Task 1 and Task 3 tests.
4. **A project manager who does not manage the person.** They may write that person's assignments on their project but not on another visible project (404). The person's assignments on a private project the manager cannot see show as "Another project", with no id, name or note. Task 3 test.
5. **Two planners publishing at once** apply each draft exactly once, and a draft outside the publisher's scope stays a draft. Task 3 test.

**Interfaces — produces:**
- **Modes and shapes:**
  - `HOURS_MODES = ["PER_DAY", "TOTAL"] as const`, `HoursMode`.
  - `SCHEDULE_RANGE_MAX_DAYS = 91`, `ASSIGNMENT_SPAN_MAX_DAYS = 366`, `REPEAT_WEEKS_MAX = 4`.
  - `interface AssignmentShape { startDate: string; endDate: string; mode: HoursMode; minutesPerDay: number | null; totalMinutes: number | null; includeNonWorking: boolean; repeatWeeks: number | null; repeatUntil: string | null }`.
  - `interface DayRules { workingDays: readonly number[]; holidayKeys: ReadonlySet<string> }`.
- **Where minutes fall:**
  - `occurrences(a): { startDate: string; endDate: string }[]`: one span without recurrence; otherwise the start shifted by `7 * repeatWeeks * k` while the shifted start ≤ `repeatUntil`.
  - `fallsOn(dateKey, rules, includeNonWorking): boolean`: true when non-working days are included; otherwise a working weekday that is not in `holidayKeys`.
  - `assignmentDays(a, rules, range: { from: string; to: string }): Map<string, number>`: for each occurrence that overlaps the range, its days that `fallsOn` (over the **whole occurrence**). PER_DAY puts `minutesPerDay` on each; TOTAL spreads `totalMinutes` over them (earliest first get the remainder). Only keys inside the range are kept.
  - `spanLastDay(a): string`: the last occurrence's end date.
- **Capacity and heat:**
  - `capacityByDay(range, capacity: Capacity, holidayKeys, timeOffMinutes: ReadonlyMap<string, number>): Map<string, number>`: daily capacity on a working non-holiday day less the time off, floored at 0; 0 otherwise.
  - `HEATS = ["under", "at", "over"] as const`, `Heat`.
  - `heatOf(scheduled: number, capacity: number): Heat | null`: `over` when scheduled > capacity; `at` when equal and > 0; `under` when capacity > 0 and scheduled < capacity; else null.
- **Date edits:**
  - `moveAssignment(a, newStart: string): AssignmentShape`: keeps the length; `repeatUntil` shifts by the same number of days.
  - `resizeAssignment(a, edge: "start" | "end", dateKey): AssignmentShape`: clamps so start ≤ end.
  - `splitAssignment(a, at: string, rules): [AssignmentShape, AssignmentShape]`: `startDate < at ≤ endDate`, else `RangeError("Split inside the assignment.")`. Throws `RangeError("Split works on a single assignment; edit the series instead.")` when `repeatWeeks`. A TOTAL splits into the minutes `assignmentDays` puts before `at` and the rest.
- **Lanes:** `stackLanes<T extends { id: string; startDate: string; endDate: string }>(bars: T[]): Map<string, number>`: greedy interval packing by start date, then id.
- **`schemas.ts`:**
  - `assignmentInputSchema = z.object({ userId: z.string().min(1), projectId: z.string().min(1), taskId: z.string().min(1).nullable().default(null), startDate: z.iso.date(), endDate: z.iso.date(), mode: z.enum(HOURS_MODES), minutesPerDay: z.int().min(1).max(1440).nullable().default(null), totalMinutes: z.int().min(1).max(1440 * ASSIGNMENT_SPAN_MAX_DAYS).nullable().default(null), includeNonWorking: z.boolean().default(false), note: z.string().trim().max(1000).default(""), repeatWeeks: z.int().min(1).max(REPEAT_WEEKS_MAX).nullable().default(null), repeatUntil: z.iso.date().nullable().default(null) })`.
  - Refinements, each with its path:

    - PER_DAY needs `minutesPerDay`: `"Enter the hours per day."`.
    - TOTAL needs `totalMinutes`: `"Enter the total hours."`.
    - `repeatWeeks` and `repeatUntil` together: `"Pick when the repeat ends."`, `repeatUntil`.
    - `repeatUntil` ≥ start and ≤ start + 1 year: `"A repeat ends within a year."`.
  - `assignmentPatchSchema`: every field optional, explicit (no `.partial()`, which keeps defaults).

  - **`assignments.ts`** (every export takes `db: Database, viewer: Viewer`; each write runs in a transaction):
    - **`createAssignment(db, viewer, input: AssignmentInput): Promise<string>`** checks, in order:
      - `assertCan(actor, "assignment.write", { kind: "entry", userId, projectId })`.
      - The person is an active member: `loadViewer`, 404 otherwise.
      - `requireAssignable(db, viewer, person, input)`:
        - The project exists in the workspace and is visible to the actor (`projectResource` + `project.view`, 404 otherwise).
        - `trackingBlock({ project, task, tags: [] })`, as `ScheduleError("INVALID", message)`.
        - The project is visible to the person (`projectResource` for the person + `project.view`), else `ScheduleError("INVALID", "Add <name> to the project first.")`.
        - A task is one of `visibleTasksFor(db, personViewer, { projectIds: [projectId] })`, else `"This task is not available to <name>."`.
      - A TOTAL is at most 1440 × the falling days of one occurrence: `"That is more than 24 hours a day."`.
      - Inserts a draft (`published false`, `createdBy` the actor).
    - **`updateAssignment(db, viewer, id, patch: AssignmentPatch): Promise<string>`:**
      - Loads the working row by id: a draft (not a tombstone), or a published row with no draft. Outside `assignmentScopeFilter`, or not found: 404.
      - `assertCan` on the old (userId, projectId) and on the new ones; `requireAssignable` when the person, project or task changes.
      - A draft is updated in place. A published row gets a new draft copy with the patch and `replacesId` = its id; a second edit goes through the draft's id.
      - Returns the working id.
    - **`deleteAssignment(db, viewer, id)`:**
      - A new draft (no `replacesId`) is deleted.
      - A draft that replaces a published row becomes a tombstone (`deleted true`).
      - A published row with no draft gets a tombstone draft.
    - **`copyAssignment(db, viewer, id, to: { userId?: string; startDate: string })`:** a new draft with the same fields, moved (`moveAssignment`), checked like a create.
    - **`splitAssignmentAt(db, viewer, id, at: string)`:** `splitAssignment` with the person's `DayRules` (working days, holiday keys over the span). The first part is an update of `id`; the second, a create.
    - `ScheduleError extends Error { code: "INVALID" | "NOT_FOUND" }`.
  - **`publish.ts`:**
    - **`publishSchedule(db, viewer, now = new Date()): Promise<{ changed: number; notified: number }>`:**
      - `assertCan(actor, "schedule.publish", { kind: "none" })`, then a transaction under `pg_advisory_xact_lock(hashtext('schedule:' || workspaceId))`.
      - Takes the drafts (`not published`) in `assignmentScopeFilter`, each also passing `can(actor, "assignment.write", …)`.
      - For each: a tombstone deletes its replaced row (cascading to itself); a replacing draft deletes the replaced row and becomes published with `replacesId` null; a new draft becomes published.
      - Inserts an `assignment_publish` row.
      - The changed people are the draft's and the replaced row's users. For each, `enqueueEmail` with `kind` `schedule.published:<publishId>:<userId>` and `schedulePublishedEmail`. The list is their published assignments overlapping today … today + 27 in their own timezone, re-checked so a project they can no longer see is left out.
      - Returns the counts. After commit the action calls `drainSoon()`.
    - **`discardDrafts(db, viewer): Promise<number>`:** deletes the drafts in the same scope.
  - **`emails.ts`:** `schedulePublishedEmail({ appUrl, slug, workspaceName, personName, items: { startDate, endDate, projectName, taskName, minutesPerDay, totalMinutes, mode, note }[] }): Email`:
    - Subject: `"Your schedule in <workspace> was updated"`.
    - Intro: one line per item, `"Nov 16 – Nov 20 · Website · 4:00 a day"`.
    - With no items: `"You have nothing scheduled in the next four weeks."`.
    - Link: My schedule.
  - **`milestones.ts`:**
    - `createMilestone(db, viewer, input)`, `updateMilestone(db, viewer, id, patch: Partial<MilestoneInput>)` and `deleteMilestone(db, viewer, id)`, each under `assertCan(actor, "milestone.manage", await projectResource(…))`.
    - `listMilestones(db, viewer, range)`: the projects the viewer may view; `editable` per `can`.
  - **`read.ts`:**
    - **`readSchedule(db, viewer, opts: { from: string; to: string; plan: "working" | "published"; userIds?: string[]; projectIds?: string[]; groupIds?: string[] }): Promise<ScheduleDTO>`:**
