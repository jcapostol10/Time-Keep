# Phase 6c — Expenses: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Anyone records what they spent on a project (a fixed amount or a quantity of a unit, billable or not, with a receipt); the people in charge see, filter, report and export it; expenses join approvals and locks like time, and the Profit tab counts them.

**Architecture:** Two tables, `expense_category` and `expense`, in migration `0018_phase6c`; expenses are always in the workspace currency and never converted. One service (`server/expenses.ts`) writes `expense`, through one guard (`assertExpenseWritable`, the entry guard's period lookup over the expense's date), under the person's advisory lock. One scope rule, the matrix's `expense.read` / `expense.write` on an entry-shaped resource (a person and a project), filters every read; `expenseScopeFilter` is the only SQL form of it. The Expenses report and the Profit tab's expense side are one aggregate (`expenseTotalsBy`). Receipts live in the private bucket under `receipts/<workspace>/<expense>`, sniffed by magic bytes, shown through 5-minute presigned URLs; the browser shrinks photos before upload. "Download receipts" is always an export job that zips them.

**Tech stack:** Drizzle + Postgres (migration `0018_phase6c`), `packages/core` pure maths (Vitest), Next.js 16 route handlers and server actions, react-query, `fflate` for the zip, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-05-phase-6-design.md` (decisions 1, 14–19, Data model "Migration 0018_phase6c", Access rules, Tests).

## Global constraints

- **Money is integer minor units + ISO 4217; never floats.** Expenses are on the cost side: **always in the workspace currency** (`workspace_settings.currency`); nothing is converted, two currencies are never added.
- A category is `FIXED` (an amount is typed) or `UNIT` (a unit name and a price per unit; a quantity in hundredths is typed, the unit price is **snapshotted on the expense**, `amount = round-half-up(quantityCenti × unitPriceMinor / 100)` in BigInt). Every expense stores `amount_minor`; an amount must be > 0.
- An expense has a person, a **required** project, a category, a **local date** (`date`, no time, no timezone), billable, a note and an optional receipt. It belongs to the approval period that holds its date (date keys compare directly; periods are the workspace's).
- **Who** (`packages/core/src/permissions.ts`): `expense.read` is `entry.read`'s row, `expense.write` is `entry.write`'s row, both on `{ kind: "entry", userId, projectId }` (an expense is a person's and a project's, the shape of an entry); `expenseCategory.manage` is owners and admins. A member asking for anyone else's expense is a 404. Expense amounts are visible to whoever may see the expense (`report.viewAmounts` governs rated time, not what a person typed).
- **Receipts**: JPEG, PNG, WebP or PDF, at most `4 * 1024 * 1024` bytes, type decided by **magic bytes** (the declared MIME is refused when it disagrees), stored in the private `S3_EXPORT_BUCKET` (`uploadExport`) under `receipts/<workspaceId>/<expenseId>` and `…/<expenseId>.thumb.jpg`, opened through a 5-minute presigned inline URL. The browser scales a photo to 2,000 px and makes a 320 px JPEG thumbnail; the server never decodes an image. A PDF has no thumbnail (a file icon).
- `assertExpenseWritable` is called by every exported writer of `server/expenses.ts` (`expense-writable-coverage.test.ts` fails otherwise); it is the entry guard's lookup: the lock date refuses members' and managers' writes, a PENDING or APPROVED period refuses them and asks owners and admins for a `note` (`NOTE_REQUIRED` → `fieldErrors.note`, logged as `ADMIN_EDIT` with `approval_event.expense_id`). Every guarded write takes `timerLock(workspaceId, userId)` inside its transaction.
- Date maths only via `packages/core` (`localDateKey`, `periodContaining`, `addDaysInZone`); never `n * 86_400_000`.
- `time_entry` is not written by this phase. `expense` is written only by `server/expenses.ts`.
- The migration is additive; previews never migrate: **stop after Task 2**, push, and ask the owner to run the Migrate shared database workflow on the branch (approval needed).
- Tests first. E2E: unticked lines in `docs/E2E_COVERAGE.md` and a failing spec before UI code; a line is ticked only after its test was seen to fail with the behaviour broken, and the commit message records the break.
- The preview lane stays under 9 minutes: Task 6 measures it and moves a mature spec to `@nightly` if needed.
- Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Finished branches merge to `main` and push (standing preference, 2026-11-09); the branch is deleted once merged.

## Review focus

1. Receipt bytes that lie: a JPEG renamed `.png` (stored as `image/jpeg`), a file declared `image/png` whose bytes are a PDF (refused), a 4 MB PDF (accepted) and one byte more (refused) — Task 3 tests.
2. An expense dated inside a PENDING period: its owner's edit refused with `PENDING_MESSAGE`, a manager of the person refused the same way, an admin asked for a note and then logged, and a member's expense before a rolling lock date refused — Task 3 tests.
3. Quantities at the edges: `"0"` refused, `"12.345"` refused (two decimals at most), `"1,5"` accepted as 150, a unit price of 1 minor × 150 centi → 2 (half up), a fixed amount of `"0"` refused — Task 1 tests.
4. Scope on every read: a manager's Expenses page, report and Profit tab hold only their people's expenses and those on their projects; a member's only their own unless the workspace shows the team's time; nobody's receipt opens outside that — Task 4 tests.
5. Profit on a project billed in USD (workspace PHP) with PHP expenses: the group's time stays out of profit, its expenses still count (billable ones as revenue, all as cost), and the Profit export prints the two expense columns — Task 4 test.
