# Phase 2 — Projects, clients, tasks, tags, timesheet, calendar — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Phase 1 project and tag stubs with clients, projects (with access rules and detail pages), tasks and tags, and add the Timesheet and Calendar views, so one entry can be made and edited from the timer, the weekly grid or the calendar and looks the same in all three.

**Architecture:** One migration adds the catalog tables and extends `project` and `tag` in place. Pure rules and maths (access, tracking blocks, timesheet cell planning, calendar geometry) live in `packages/core` with unit tests. New server modules under `apps/web/src/server/catalog/*` own clients, projects, tasks and tags; the entry service gains the role-aware usability check and a range read; every entry write still goes through `time-entries.ts`. Pages are App Router server components with client components for tables, dialogs, the grid and the calendar; reads for the grid and calendar go through one `time-entries/range` route and share the tracker's react-query key prefix, so an edit anywhere refetches everywhere.

**Tech Stack:** Next.js 16 App Router, React 19, Drizzle, Better Auth, react-query, react-hook-form + zod, shadcn/ui, Playwright, Vitest. No new runtime dependencies (drag and keyboard handling are hand-written on pointer and keyboard events).

**Spec:** `docs/superpowers/specs/2026-10-20-phase-2-design.md`

## Global Constraints

- Timestamps are UTC; render in the viewer's timezone via `resolveViewerPrefs`. Date, time and duration maths only through `packages/core` (`zonedDateTimeToInstant`, `addDaysInZone`, `weekBounds`, `localDateKey`, `minutesSinceMidnight`, `parseDuration`, `formatDuration`).
- Every query is scoped by `workspaceId` and role-checked. Server actions and route handlers call `requireWorkspaceAccess(slug, minRole)` first; pages use `requireWorkspacePage`. A private project the user is not on is indistinguishable from a project that does not exist.
- Time entries are written only through `apps/web/src/server/time-entries.ts`.
- Every new table calls `.enableRLS()`; `rls.test.ts` enforces it. New tables are added to `truncateAll` in `apps/web/test/db.ts`.
- Migrations are generated with `pnpm db:generate` and never edited after they are applied. Decision 3 in the spec accepts the one-minute window from replacing the project-name unique index.
- Test-first from Phase 2: a feature's coverage lines in `docs/E2E_COVERAGE.md` (unticked) and its failing Playwright tests exist before its app code. A line is ticked only when its test passes against the finished feature; the commit message records that the test failed first.
- `test.skip` / `test.fixme` are lint errors in `e2e/`.
- Every page works at 375px wide (grids scroll horizontally with a sticky first column).
- Copy and assets are our own; never the competitor's.
- The e2e suite stays under 10 minutes on a Vercel preview with `failOnFlakyTests` on.
- Commit after each task; messages explain what and why; end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **A stale picker:** a member's picker still lists a project that an admin just archived or made private. Starting a timer must fail with the `trackingBlock` message (or "Project not found."), never create the entry, and the picker must refresh. Test in Task 3 (service) and Task 6 (the "archived projects take no new time" test asserts the toast).
2. **Garbage or huge timesheet input:** `abc`, `-1`, `1000h` in a cell must revert the cell and toast, with no entry written. Test in Task 12.
3. **Calendar drags that leave the grid:** a drag that ends above 00:00, below 24:00 or outside the column must clamp to the day, never produce an end before its start, and never a zero-length entry. Tests in Task 13 (maths) and Task 14 (UI).
4. **An entry crossing midnight edited from the timesheet:** lowering its cell shortens it from the end; it stays under its start day. Test in Task 10.
5. **Copying a week across a daylight-saving change:** every copied entry keeps its wall-clock start and its duration. Test in Task 10.
