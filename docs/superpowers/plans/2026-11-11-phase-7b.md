# Phase 7b — Forecast and Assignments report: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A project's Budget tab predicts where the published plan takes it: tracked work plus the scheduled future against the estimate, with the projected completion date and the overrun. A new Reports tab compares the plan with what was tracked, by person, project or date, and exports it.

**Architecture:**
- **One expansion of the published plan into per-day minutes:** `server/schedule/plan-days.ts`. It does for a filter what `readSchedule` does for the grid (person's working days, holidays, recurrence, a total spread over its whole occurrence), and both the forecast and the report read it.
- **Pure maths in core:**
  - `forecast.ts`: cumulative projection, completion date, overrun in both units, proportional and half up.
  - `assignments-report.ts`: rows and variance.
- **Money for scheduled time:** core `resolveRate` over the project's billable rate rows, per person, task and day, in the project's currency, and only when the project is billable by default.
- **The report:** a `reportRoute` view under the Reports page's rule, with members pinned to themselves. Its export always streams, like Profit, so the `export_report` enum, and therefore the migrations, are untouched.

**Tech Stack:** `packages/core` (Vitest), Drizzle reads, Next.js 16 routes, react-query, recharts, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-11-phase-7-design.md`, decisions 19–22 and Tests (7b).

## Global Constraints

- **The published plan only** (decision 19). Drafts never enter the forecast or the report.
- **Raw time** (rounding never applies); work entries only; stopped, live entries.
- **Money:**
  - Integer minor units, BigInt half up for the proportional overrun, never floats for money.
  - Scheduled money is in the project's currency (`projectCurrency`). A day with no rate in force is counted in `unratedSeconds`.
- **Scheduled time in the forecast:**
  - It runs from tomorrow in the workspace zone to the period's end: the month for a MONTHLY estimate.
  - For a whole-project estimate, it runs to the last scheduled day, capped at 730 days after today.
- **Who:**
  - The forecast is part of the Budget tab (`project.update`).
  - The report uses `page.view` reports. Owners and admins see everyone; a manager their scope (own, managed people, managed projects, for both assignments and entries); a member their own only, whatever "members see the team's time" says (a plan is not time).
- **No migration.** The Assignments export always streams, and a body over `MAX_STREAMED_BYTES` is a 413, as Profit's is.
- Tests first; e2e lines unticked and failing before UI code; each ticked after a break was seen to fail.

## Review Focus

1. **Tracked already past the estimate:**
   - Completion reads "Reached on <date>", the first day the tracked series crossed it.
   - Overrun = tracked − estimate + everything scheduled.
   - Task 1 test.
2. **A whole-project estimate whose plan never reaches it:** completion is null ("Not reached by the published plan") and the overrun is 0. Task 1 test.
3. **A scheduled day for someone with no rate:** counted in `unratedSeconds`. The money projection includes only rated days, and the overrun's money share stays proportional over the rated projection. Task 2 test.
4. **An assignment on a project the viewer cannot see:** it never appears in the report, unlike the grid's "Another project" (a report row needs a label). A member sees only their own rows, even with the team's time shown. Task 2 test.
5. **The report's date grouping:** a tracked entry falls on its owner's own local day; a scheduled day is a date key. A day with only scheduled or only tracked time still has a row. Task 2 test.

### Task 1: Core — forecast maths, report rows, query key, export columns

**Files:**
- Create: `packages/core/src/forecast.ts` (+ `forecast.test.ts`), `packages/core/src/assignments-report.ts` (+ `assignments-report.test.ts`).
- Modify: `packages/core/src/reports.ts` (+ test), `report-export.ts` (+ test), `index.ts`.

**Interfaces — produces:**
- **`forecast.ts`:**
  - `interface ForecastDay { dateKey: string; seconds: number; minor: number }`.
  - `interface Forecast { kind: "TIME" | "MONEY"; estimate: number; trackedSeconds: number; trackedMinor: number; scheduledSeconds: number; scheduledMinor: number; unratedSeconds: number; projectedSeconds: number; projectedMinor: number; reachedOn: string | null; completionDate: string | null; overrunSeconds: number; overrunMinor: number; series: { dateKey: string; value: number }[] }`.
  - `forecast(input: { kind; estimate: number; trackedSeconds: number; trackedMinor: number; trackedReachedOn: string | null; scheduled: readonly ForecastDay[]; unratedSeconds: number }): Forecast`:
    - `series` is the cumulative projection in the estimate's unit, starting from the tracked total (scheduled days ascending).
    - `completionDate` is the first scheduled day the cumulative value reaches the estimate. It is null when the estimate was already reached (then `reachedOn` = `trackedReachedOn`) or never is.
    - Overrun in the estimate's unit: `max(0, projected − estimate)`.
    - The other unit: `proportion(other, overrun, projected)` = BigInt `(other × overrun × 2 + projected) / (2 × projected)`, which is 0 when `projected` is 0.
  - `proportion(value: number, part: number, whole: number): number`, exported.
- **`assignments-report.ts`:**
  - `ASSIGNMENT_GROUP_KEYS = ["user", "project", "day", "week"] as const`, `AssignmentGroupKey`.
  - `interface PlanRow { userId: string; projectId: string; dateKey: string; seconds: number }`.
  - `interface AssignmentsRow { key: string; label: string; scheduledSeconds: number; trackedSeconds: number; varianceSeconds: number; variancePercent: number | null }`.
  - `assignmentsRows(scheduled: readonly PlanRow[], tracked: readonly PlanRow[], by: AssignmentGroupKey, opts: { weekStart: number; labels: ReadonlyMap<string, string> }): { rows: AssignmentsRow[]; totals: AssignmentsRow }`:
    - Variance = tracked − scheduled. Percent = `round(variance × 1000 / scheduled) / 10` when scheduled > 0, else null.
    - Rows are sorted by label for user and project, by key for day and week.
    - The label for day and week is `formatDateKey(key)` (a week as "Week of <date>").
    - A key with no label in the map reads "(former member)" for user and "(deleted project)" for project.
- **`reports.ts`:**
  - `reportQuerySchema` gains `assignmentsBy: z.enum(ASSIGNMENT_GROUP_KEYS).default("user")` (in `SCALAR_KEYS`).
  - `ReportView` gains `"assignments"`.
- **`report-export.ts`:** `assignmentsColumns(by: AssignmentGroupKey, prefs: ViewerPrefs): ExportColumn<AssignmentsRow>[]` gives `[Person|Project|Date|Week, Scheduled, Tracked, Variance, Variance %]`:
  - Durations as `formatDuration` with the viewer's format, and a negative variance with a leading `-`.
  - Percent printed with one decimal, or empty.

### Task 2: Server — plan days, the forecast, the report, routes and exports

  - `server/task-visibility-coverage.test.ts`, if a new module imports `task`.

**Interfaces:**
- **Consumes:** Task 1's interfaces; 7a's `publishedPlanWhere`, `overlapsRange`, `dayRulesFor`; `peopleContext` and `workspaceZone`; `projectCurrency`; `scopeFilter`; `resolveRate`.
- **Produces:**
  - **`plan-days.ts`:**
    - `interface PlanDay { userId: string; projectId: string; taskId: string | null; dateKey: string; minutes: number }`.
    - `publishedPlanDays(db, workspaceId, opts: { from: string; to: string; userIds?: string[]; projectIds?: string[]; where?: SQL }): Promise<PlanDay[]>`.
    - People come from `peopleContext` including deactivated ones. A user with no membership uses `DEFAULT_CAPACITY`'s working days and no holidays. Holidays cover every occurrence's whole span.
  - **`forecast.ts`:** `projectForecast(db, viewer, projectId, estimate: Estimate, currency: string, now: Date): Promise<Forecast | null>`, null without an estimate.
    - **Tracked:** raw stopped work in the period up to now; seconds, plus the billable amount in `currency`, as `progressFor` measures them.
    - **`trackedReachedOn`:** the first local day the tracked cumulative value reached the estimate, from the daily measure.
    - **Scheduled:** `publishedPlanDays` for the project from tomorrow to the period end (MONTHLY) or `tomorrow + 730`.
    - **Money:** each day's minutes × the rate `resolveRate` picks for `{ userId, projectId, taskId, start: that day's midnight in the workspace zone, currency }`, over the workspace's billable rate rows in `currency`. Zero, and counted as unrated, when the project is not billable or no rate is found.
  - **`BudgetDTO.forecast: Forecast | null`:** the Budget tab shows it when the published plan has anything scheduled in the period, or when the estimate was already reached.
  - **`report.ts`:** `assignmentsReport(db, viewer, query: ReportQuery, prefs: ViewerPrefs, now?): Promise<AssignmentsReport>`.
    - **Range:** `resolveReportRange` in the viewer's zone, as date keys.
    - **Scope:** a member is pinned to themselves; otherwise `effectiveQuery`'s `userIds`, `groupIds`, `clientIds` and `projectIds`.
    - **Assignments:** filtered by the actor's write scope (`assignmentScopeFilter`) and by `visibleProjectFilter(viewer)`.
    - **Entries:** `scopeFilter`, except that members see only their own, on visible projects, work only. Each entry is bucketed on its owner's local day (`user.timezone`, else the workspace's).
    - **Labels:** people's names and project names.
    - `lib/report-types.ts`: `AssignmentsReport { from: string; to: string; label: string; by: AssignmentGroupKey; rows: AssignmentsRow[]; totals: AssignmentsRow }`.
  - **Route:** `GET /api/w/[slug]/reports/assignments` through `reportRoute` (the default `page.view` reports).
  - **Exports:**
    - `FileReport` gains `"assignments"`; `exportTable` case `assignments` uses `assignmentsColumns`; `countExportRows` counts the rows.
    - The PDF title is "Assignments report", with the total row.
    - The export route's `requestSchema.report` gains `"assignments"`, and it always streams: no job, like Profit.
