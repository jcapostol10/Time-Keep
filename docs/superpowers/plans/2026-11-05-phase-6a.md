# Phase 6a — Cost, profit and currencies: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entries carry what the work cost, reports show cost and profit to the people allowed to see them, and a client can be billed in its own currency without any amount being converted or added across currencies.

**Architecture:** Cost rates are `rate` rows with `kind = 'cost'` at two levels; the one rating statement (`rateEntriesSql`) snapshots billable and cost on the entry, and a billable rate only applies in its own currency. The report engine adds cost, profit and other-currency amounts as measures of the same queries, and zeroes cost for viewers without `report.viewCosts`. No new table.

**Tech stack:** Drizzle + Postgres (migration `0016_phase6a`), `packages/core` pure maths (Vitest), Next.js 16 server actions and route handlers, react-query, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-05-phase-6-design.md` (decisions 1–9, "Part 1 and 2 — what is built in 6a").

## Global constraints

- Money is integer minor units + ISO 4217 code; never floats. Amounts use `amountFor` (BigInt half up) in core and `round(numeric)` in SQL.
- **No currency conversion.** Two currencies are never added. Cost is always in the workspace currency.
- Cost levels are `project_member` then `member`; no other level takes a cost row.
- A billable rate applies only to entries in its own currency (`rate.currency` = the entry's currency).
- An entry's currency is its project's client's currency, else the workspace currency.
- Cost and profit are zeroed **in the engine** for viewers without `report.viewCosts`; share links never carry them.
- `time_entry` is written only by `apps/web/src/server/time-entries.ts` and `packages/db/src/rates-sql.ts`.
- The migration is additive; previews never migrate: **stop after Task 2**, push, and run the Migrate shared database workflow on the branch (ask the owner first).
- Tests first. E2E: unticked lines in `docs/E2E_COVERAGE.md` and failing specs before app code; a line is ticked only after its test was seen to fail with the behaviour broken, and the commit message records the break.
- The preview lane stays under 9 minutes: `approvals.spec.ts` and `time-off.spec.ts` move to `@nightly` in Task 5.
- Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Merging and pushing `main` need the owner's approval.

## Review focus

1. A viewer without `report.viewCosts` asking the Profit route, a Detailed page or an export directly: cost, profit and the uncosted count read 0 and the columns are absent (Task 4 tests every entry point).
2. An entry on a project billed in another currency where only a member or workspace rate exists: unrated and counted, never rated at face value (Task 2).
3. Two currencies in one range: totals keep them apart, `addTotals` merges per currency, sorting by amount does not mix them (Tasks 1 and 4).
4. A client's currency changed while it has rated entries: only that client's projects' rates and entries are relabelled, numbers unchanged, other clients untouched (Task 3).
5. A running timer, a break and a person with no cost rate: cost amount null while running and computed on stop; a break never costed; the uncosted count counts stopped work entries only (Tasks 2 and 4).
