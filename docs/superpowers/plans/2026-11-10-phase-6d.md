# Phase 6d — Invoicing: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Owners and admins bill a client: an invoice in the client's currency, numbered from a workspace sequence, filled from the report engine (billable time and expenses, invoiced once) and manual lines, with discount and two taxes; sent as a frozen PDF by email with a public link; paid by recorded payments; produced on a schedule by the daily job.

**Architecture:** Migration `0019_phase6d`: `invoice_settings`, `invoice`, `invoice_item`, `payment`, `recurring_invoice`, `time_entry.invoice_id` (+ a partial index), the foreign key on `expense.invoice_id`, and `email_outbox.attachment_key/attachment_name`. Stored status is `DRAFT | SENT | VOID`; `PAID`, `PARTIALLY_PAID` and `OVERDUE` are computed by one core function and one SQL `CASE` tested to agree. One service directory `server/invoices/*` writes `invoice`, `invoice_item`, `payment`, `recurring_invoice`; the entry service and the expense service stay the only writers of their tables (`markInvoiced` / `releaseInvoiced`). An import runs the report engine's conditions (billable, rated, the invoice's currency, no invoice, the client's projects, the workspace rounding rule) and marks exactly what it selected under a per-client advisory lock. The entry guard refuses any write to an invoiced entry with the invoice's number; the rate job skips invoiced time. Sending renders the invoice template through the report PDF printer into the private bucket and enqueues the client's email with the file attached; the public page `/invoice/<token>` (sha256 stored) shows it and streams the frozen PDF under the share export's rate limit. The daily job runs recurring templates (one invoice per template and period) and sends each overdue email once.

**Tech stack:** Drizzle + Postgres (migration `0019_phase6d`), `packages/core` pure maths (Vitest), Next.js 16 route handlers and server actions, react-query, nodemailer attachments, headless Chromium (`report-pdf.ts`), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-05-phase-6-design.md` (decisions 1, 20–28, Data model "Migration 0019_phase6d", Access rules, Tests, Risks).

## Global constraints

- **Money is integer minor units + ISO 4217; never floats; nothing is converted.** An invoice takes its client's currency when created (`client.currency ?? workspace`) and keeps it; only time rated in that currency and expenses in it (expenses are always the workspace currency) can be imported.
- **Numbering** (decision 20): `invoice_settings` holds `number_prefix` (default `INV-`), `next_number` (default 1), `number_padding` (default 4) → `INV-0001`; the next number is taken under `SELECT … FOR UPDATE` of the settings row; the number is editable while the invoice is a draft; unique per workspace.
- **Status** (decision 21): stored `DRAFT | SENT | VOID`; `invoiceStatus(invoice, todayKey)` in core and `invoiceStatusSql(todayKey)` in SQL give `PAID` (paid ≥ total, total > 0 or paid > 0), `PARTIALLY_PAID` (0 < paid < total), `OVERDUE` (SENT, unpaid, `due_date < today` in the workspace timezone), else the stored value. Nothing stores a computed status; the daily job sends the overdue email once per invoice (`kind` `invoice.overdue:<id>`).
- **Maths** (decision 22): a manual line is `round_half_up(quantity_centi × unit_price_minor / 100)` (core `lineAmount`); an imported time line's amount is the engine's amount for the group (the sum of each entry's rounded amount); hours show to two decimals; `subtotal = Σ lines`; `discount = round_half_up(subtotal × discount_bps / 10000)`; each tax `= round_half_up((subtotal − discount) × tax_bps / 10000)`, not compounded; `total = subtotal − discount + taxes`. Percents are hundredths of a percent (`bps`, 0–10000).
- **Invoiced once** (decision 23): `time_entry.invoice_id`, `expense.invoice_id`; an import takes stopped, billable, rated (`amount_minor is not null`), live entries with `rate_currency = invoice.currency` and `invoice_id is null` on the client's projects, under `pg_advisory_xact_lock(hashtext('invoice:' || client_id))`, and throws if the `UPDATE … RETURNING` count differs from the selection. Removing a line, deleting a draft or voiding releases. An invoiced entry is read-only for everyone: the guard's message is `This entry is on invoice <number>.`; the rate job's `entriesFrom` adds `invoice_id is null`; Detailed shows an `Invoiced` badge and the query gains `invoiced: all | yes | no`.
- **Sending** (decision 24): `sendInvoice` renders the PDF, stores it at `invoices/<workspace>/<invoice>.pdf` in `S3_EXPORT_BUCKET`, sets `status SENT`, `sent_at`, `pdf_key`, a public token (sha256 stored), and enqueues the client's email (`kind` `invoice.sent:<id>`) with `attachment_key` / `attachment_name` (`<number>.pdf`) and the public link; `markSent` does the same without the email. Branding comes from `invoice_settings` (company name, address, tax line, default notes, payment terms days default 30, default tax names and bps) and `workspace.logo`.
- **Public view** (decision 25): `/invoice/[token]`: no session, `X-Robots-Tag: noindex`; a draft, a void invoice, an unknown or revoked token → the same 404; `Download PDF` streams the frozen file, one download per invoice per 10 s (`invoice.last_download_at`, the `claimShareExport` pattern).
- **Payments** (decision 26): date, amount > 0, note, on a SENT invoice; `paid > total` is refused with `This payment is more than the balance.`
- **Recurring** (decision 27): `WEEKLY` on a weekday (0–6) or `MONTHLY` on a day 1–31 clamped to the month's last day; `start_date`, optional `end_date`; fixed manual lines (jsonb); optionally "import the period just ended" with a group key; mode `DRAFT` or `SEND`. The daily job creates at most one invoice per template and period (`unique (recurring_id, period_key)`); `SEND` without a client email leaves a draft and emails the active owners and admins (`kind` `invoice.recurring-unsent:<template>:<period>`).
- **Who** (decision 28): `invoice.manage` is owners and admins (`ADMINS`); the Invoices page is a 404 and the routes a 403 for anyone else. `external_ref` and `server/invoices/sync.ts` (a typed, empty adapter registry) are the accounting hook; nothing calls out.
- A client's currency change is refused while the client has invoices (`CatalogError("CONFLICT", "This client has invoices in <CUR>; its currency cannot change.")`) (Risks: relabelling).
- Date maths only via `packages/core` (`addDaysToKey`, `weekdayOfKey`, `localDateKey`, `zonedDateTimeToInstant`); never `n * 86_400_000`.
- The migration is additive; previews never migrate: **stop after Task 2**, push, and ask the owner to run the Migrate shared database workflow (approval needed). The partial index on `time_entry` is written `CREATE INDEX IF NOT EXISTS`; the shared database's `time_entry` holds only demo and e2e rows (customer tenants have none), so it is built by the migration, as 0007 was (ruling; the large-table rule would otherwise require a concurrent build by hand).
- PDF routes and pages that render one need Chromium traced in (`next.config.ts` `outputFileTracingIncludes`): `/api/w/*/invoices/*/pdf`, `/w/*/invoices/*` (the send action), `/api/cron/daily` and `/api/test/run-daily` (recurring `SEND`).
- Tests first. E2E: unticked lines in `docs/E2E_COVERAGE.md` and a failing spec before UI code; a line is ticked only after its test was seen to fail with the behaviour broken, and the commit message records the break. The preview lane stays under 9 minutes (5.2 today); the Mailpit-only assertions (the PDF attachment) and the daily-job flows go to the nightly lane.

## Review focus

1. Two concurrent imports of the same client and range (two connections, `Promise.all`): the second takes nothing and the entries carry exactly one invoice — Task 3 test.
2. An invoiced entry under every writer: edit, delete, bulk edit, split, duplicate's source untouched, continue (a new entry: allowed), the timesheet cell, the import, and the admin note path (a note does not unlock an invoiced entry) — Task 2 test; `deleteProject` with invoiced time refused — Task 2 test.
3. Totals at the edges: a 7.5% discount on 1 (minor) → 0; two taxes on an odd subtotal round each on its own; `discount_bps 10000` → total = taxes on 0 = 0; a line of 0.33 h at 100.00 → the engine's amount, not quantity × price — Task 1 and Task 3 tests.
4. Status on the due date: `due_date = today` is SENT, `today + 1` is OVERDUE, in the workspace timezone when the viewer's differs; a void invoice with payments reads VOID; the SQL filter agrees with core on every branch — Task 1 and Task 3 tests.
5. Recurring on month ends: a monthly template on the 31st runs on 28 February (29 in a leap year) and on 30 April; a weekly one on Monday bills the previous Monday–Sunday; a template started mid-period creates nothing for a period that began before `start_date`; a second run the same day creates nothing — Task 1 and Task 4 tests.
