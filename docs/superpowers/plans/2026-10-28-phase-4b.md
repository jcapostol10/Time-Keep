# Phase 4b — Workspace settings and power features: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Workspace settings that make the Phase 4a matrix real: hidden pages, members seeing the team's time, who creates what, required fields, force timer, breaks, and report rounding.
- Admins and managers add and edit time for the people they manage, in the tracker, timesheet and calendar.
- Bulk edit, split, favourites, project templates, an Audit report tab, and CSV import of entries.
- The `phase-4` tag, once this half's acceptance checks pass and it is merged.

**Architecture:**
- **Settings** are columns on `workspace_settings` with defaults that reproduce today's behaviour. `loadActor` reads them into `PermissionSettings`, so the 4a matrix rules (`unlessHidden`, `teamSetting`, `creator`) start answering from real data; two actions are added (`entry.writeTimes` for force timer, `import.entries`).
- **Rules on entries** (required fields, force timer, breaks) live in `packages/core` as pure functions and are applied in one place, `apps/web/src/server/time-entries.ts`, so every write path (tracker, timesheet, calendar, bulk edit, split, import) obeys them.
- **Add time for others** keeps the entry service's `(workspace, user)` scope: the scope's `userId` is the person whose entries are read or written and `actedBy` is the admin or manager acting for them. `targetScope(ctx, userId)` builds it after `entry.write`; id-based writes resolve the owner from the entry id. The timer bar stays the viewer's own.
- **Rounding** is a report rule: core `roundDuration` and a SQL twin, applied by the report engine only when the workspace sets a rule and the URL does not ask for raw time, so exports and share links follow the URL.
- **Audit** is the Detailed report with audit criteria in the URL. **Import** goes through a POST route handler (a 4 MB file is over the server-action body limit), plans in a dry run, and commits through a bulk variant of `createManualEntry` in one transaction.

**Tech Stack:** Next.js 16 App Router, React 19, Drizzle/Postgres, zod 4, react-query, Vitest, Playwright. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-27-phase-4-design.md`: Parts 4–5, decisions 5–8, 12–13, and the data model's migration `0011_phase4b`. Phase 4a (`docs/superpowers/plans/2026-10-27-phase-4a.md`) is merged; this plan is written against its code.

## Global Constraints

- **Invariant 3:** every action and route handler calls `requireWorkspaceAccess` then `authorize` (or a helper listed in `authorize-coverage.test.ts`). A role or setting that never allows the action is 403; a resource outside the actor's scope is 404.
- **Entry writes** go only through `apps/web/src/server/time-entries.ts`; the rating SQL in `packages/db/src/rates-sql.ts` stays the only other writer.
- **Decision 5:** required fields bind when an entry is stopped or saved, never when a timer starts. A refused stop keeps the timer running and names the field. "Task required" applies only when the project has active tasks. Breaks are exempt.
- **Decision 6:** a break has no project, task, tags, billable flag or amount, and reports count work only unless the Type filter says otherwise.
- **Decision 7:** force timer blocks members and managers from manual entries and from changing start, end or duration of their own entries; owners and admins, and time added for someone else, are exempt. It sits behind `planAllows(workspace, "forceTimer")`, a stub that returns true.
- **Decision 8:** nobody runs a timer for someone else. The timer bar and `startTimer`/`stopTimer`/`continueEntry` always act for the signed-in user.
- **Decision 12 and 13:** rounding changes report views, exports and share links only, per entry; amounts are recomputed from the rounded duration with the stored rate, half up, in integer maths. The tracker, timesheet, calendar and dashboard show raw time.
- **Migration `0011_phase4b`** is additive: new columns with constant defaults (no table rewrite), one new enum type, one new table with `.enableRLS()`. It runs through the "Migrate shared database" workflow before the branch's preview e2e.
- **Settings defaults reproduce today's behaviour**: nothing hidden, members see their own time only, only admins create, no required fields, no force timer, no breaks, rounding off.
- **e2e:** new lines go in `docs/E2E_COVERAGE.md` unticked and failing specs come before app code; tick a line only after its test was seen failing with the behaviour broken; fixtures from `e2e/fixtures.ts`; demo accounts only for role and isolation tests; the suite stays under 10 minutes on a preview.
- **375 px and dark mode:** the settings page, the import dialog and the tracker with the favourites strip and person picker work at 375 px.

## Review Focus

1. **Force timer meets add-for-others:** a manager under force timer adding a manual entry for themselves (403), for a person they manage (allowed), an admin editing a member's times (allowed), a member importing a CSV (403). Tests: Task 5 (service), Task 8 (actions).
2. **Required fields at the edges:** task required on a project with no active tasks (allowed) and with one (refused); a refused Stop leaves the entry running with its start unchanged; a break stops with nothing filled; bulk edit that removes the last tag when tags are required fails the whole batch. Tests: Tasks 5, 6, 9.
3. **Rounding ties and amounts:** `nearest` on an exact half rounds up; an exact step is unchanged; `down` of 14:59 at 15 min is 0; SQL and core agree on durations and on half-up amounts; the share link and the CSV export follow the URL's `rounding=off`. Test: Task 7.
4. **URL and id tampering around other people's time:** `?user=<outside scope>` on the tracker, timesheet and calendar is 404 for a manager and 403 for a member; `updateEntryAction` with another person's entry id is 404 outside scope; a target's week never lands under the viewer's own query keys. Test: Task 8.
5. **Import edge cases:** BOM and `;` delimiter, an end before its start rolls to the next day, a duplicate line imports twice (not deduplicated), an email of a deactivated member errors, 10,001 rows and a 4 MB+ file are refused before parsing, and a commit whose data changed since the dry run is refused. Test: Task 14.
